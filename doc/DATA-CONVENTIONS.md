# 날짜·금액·환율과 화면 상태 규칙

## 날짜와 시각

- 거래일·환전일·매매일·메모일·스냅샷 매도 확인일·스냅샷 등록일은 **날짜 전용 값**이다. 기존 SQLite DATE 컬럼의 `YYYY-MM-DD` 형식을 유지한다. 스냅샷 등록일은 기존부터 시각을 저장하지 않았으며 순서는 일련번호로 비교한다.
- Entity 및 공용 요청·응답의 Date는 사용자 지역의 달력 날짜를 나타낸다. `dateOnlyTransformer`가 DB 문자열을 지역 자정의 Date로 바꾸고, 저장 시 지역 연·월·일만 기록한다. optional DATE의 DB NULL은 undefined로 전달한다.
- 날짜 전용 문자열을 `new Date('YYYY-MM-DD')`로 해석하거나 `toISOString().slice(0, 10)`으로 만들지 않는다. `parseDateOnly` / `formatDateOnly`를 사용한다. 월별 집계의 첫날도 이 규칙을 따른다.
- 로그와 백업 이름의 시각은 실제 순간이므로 ISO UTC 문자열을 사용한다. 날짜 전용 값과 시각을 섞지 않는다. 현재 거래 DB에 새 timestamp 컬럼을 추가하지 않았다.
- 한국과 로스앤젤레스 시간대에서 연말·연초·일광절약시간 경계 날짜를 검증한다. UTC 변환으로 통계의 월/일이 전날로 이동하던 문제를 수정했다.

## 금액·수량

- 금액 저장과 업무 계산은 기존 SQLite REAL/JavaScript number를 사용한다. 이번 변경에서 정수 최소 단위 또는 decimal 라이브러리로 전환하지 않는다. 부동소수 오차는 허용 범위를 정한 비교로 테스트한다.
- 거래·환전·매매 효과와 평균 원가 계산은 중간에 반올림하지 않는다. 주식 수량은 INTEGER로 저장한다. 매매 수량은 양의 정수이며 보유수량 입력도 정수만 허용한다. 소수 입력은 폼·IPC·서비스에서 오류로 처리하고 임의로 반올림하거나 절삭하지 않는다.
- 일반 거래의 음수 금액은 환불 등의 기존 의미를 유지한다. 매매 수량은 양수이며 최종 보유수량이 음수면 저장을 롤백한다.
- 화면 통화 표시는 KRW/JPY 0자리, USD 2자리다. 화면 표시를 위한 반올림은 원장 값을 변경하지 않는다. 보유종목 응답의 표시용 원가는 기존 2자리 반올림을 유지하며 매매 계산에는 사용하지 않는다.
- 자산 스냅샷 저장은 기존과 같이 각 계좌의 현금 합계·주식 매수금 합계·주식 평가금 합계를 각각 원화로 변환한 후 `Math.round`한다. 보고서의 주식 분류별 집계는 원화 환산값을 합산하고 표시 시 반올림한다.
- 수익률 내부 값은 0.1 = 10%인 비율이다. 화면에서 백분율로 변환한다. 비교표의 수익률 표시를 이에 맞게 수정했다. 합계 0의 비중과 원가 0의 수익률은 0으로 표시한다.

## 환율

- 환율은 외화 1단위당 KRW이며 JPY도 1엔 기준이다. 새 IPC 요청의 환율은 유한한 양수만 허용한다.
- 기존 계산과 데이터 호환을 위해 누락되거나 0인 환율은 1로 대체하는 기존 규칙을 유지한다. 스냅샷 조회/비교에서는 평가 종목의 외화 환율이 누락된 경우 안내를 표시한다. 저장된 과거 자산 합계와 거래를 일괄 재계산하지 않는다.
- 일반 거래 수수료는 거래 통화, 환전 수수료는 KRW, 매매 수수료·세금은 종목 통화다. 상세 잔고 변화 표는 REFACTORING-NOTES.md를 참고한다.

## 화면과 데이터 소유권

- main/renderer 공용 모델은 renderer 모듈을 참조하지 않는다. DB nullable 문자열이 필수 문자열 응답으로 나갈 때는 빈 문자열로, 즐겨찾기의 미지정 계좌·금액·속성은 0으로 정규화한다.
- `renderer/state/referenceData.ts`가 기준 데이터 캐시를 소유한다. IpcCaller는 저장 성공 뒤 영향받는 목록을 갱신하며 화면은 구독으로 다시 그린다. Mapper와 순수 계산 함수는 캐시를 직접 변경하지 않는다.
- 폼은 입력 중 상태를 소유하고, 조회·저장 잠금과 오류 안내는 useModalSession이 관리한다. 이전 세대의 조회 결과를 무시하고, 저장 실패는 입력값을 유지한다. 타임아웃은 main 작업 취소를 뜻하지 않으므로 자동 재시도하지 않는다.
- 새 요청/응답 변환은 반환 타입을 명시한다. 타입을 강제로 덮어쓰기보다 필수 필드 누락과 DB nullable 값을 경계에서 처리한다.
