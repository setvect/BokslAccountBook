# 리팩토링 설계·검증 기록

## 테스트 기반

- 일반 테스트에서 개발 DB 대신 임시 SQLite 파일을 생성하고 종료 시 삭제한다. 서비스 import 시 생성되는 기본 DataSource도 `NODE_ENV=test`에서는 메모리 DB만 사용한다.
- `TransactionService`는 DataSource를 생성자로 받는다. 기존 호출부는 기본 인스턴스를 사용하고, 테스트는 독립 DB 인스턴스를 주입한다.
- 샘플 생성은 `npm run sample-data` 또는 개발 메뉴로만 실행한다. 일반 Jest 대상에서 제거했다.
- 초기 타입 검사 실패는 FullCalendar v5의 `common` 타입을 v6 UI에서 참조한 것이 원인이었다. 설치된 UI와 일치하는 `core` 타입으로 변경했고 라이브러리 타입 검사를 생략하지 않았다.

## IPC 전환

- 요청·응답은 `ipcRenderer.invoke` / `ipcMain.handle`을 사용한다. UUID 기반 수동 응답 채널과 리스너를 없애고 Electron이 요청을 연결하도록 한다.
- `src/common/ipc/Contract.ts`에서 채널별 인자와 반환값을 정의한다. renderer는 기존 `window.electron.ipcRenderer` 경유 구조를 유지한다.
- main은 입력 검증 오류와 서비스 오류를 구분해 `{ ok, value/error }`로 반환한다. renderer 공통 호출부는 실패를 `IpcRequestError`로 reject한다.
- 대기 시간은 30초다. 시간 초과가 DB 작업 취소를 뜻하지 않으며, 저장 요청을 자동 재시도하지 않는다. 늦게 도착한 응답도 소비해 미처리 rejection을 방지한다.
- 호출자가 오류를 처리하면 그 처리를 따르고, 처리하지 않은 IPC rejection만 App에서 한 번 안내한다. 새 요청 실패는 기존 공통 오류 이벤트로 중복 전송하지 않는다.
- 메뉴 등의 일방향 알림은 이벤트 구독 방식을 유지한다.
- 첫 적용은 분류 조회·등록·수정·정렬·삭제다. 다른 기능은 기존 방식을 유지하는 상태에서 분류 IPC + SQLite 테스트를 통과시켰다.

## 의도한 동작 변경

- IPC 실패 후 무기한 대기하던 호출은 실패로 종료된다. 응답이 없는 요청은 시간 초과 안내가 표시된다.

### 전체 채널 적용

- 63개 요청을 모두 공통 방식으로 전환했다. preload의 범용 send/once와 공통 오류 이벤트를 제거했다. 요청과 3개 메뉴 알림은 각각 허용 목록으로 제한한다.
- main 진입점에서는 필드 타입, 필수 값, 유한한 숫자, 날짜, 열거형, Set, 배열을 검증한다. 금액 계산·계좌 존재·매도 가능 수량 등 업무 판단은 서비스에서 수행하고, 3단계에서 규칙과 트랜잭션 검증을 강화한다.
- 즐겨찾기 서비스 저장·수정의 인자를 응답 모델에서 요청 모델로 바로잡았다. 검색 대상 창이 없으면 false로 응답한다.
- 공용 검색 모델의 AccountType을 src/common으로 옮겨 renderer에 대한 역참조를 제거했다.
- 전체 채널 등록 및 잘못된 요청 거절, preload 요청·알림 분리, 원래 요청으로 전달되는 서비스 오류, 처리되지 않은 오류의 단일 안내를 테스트했다.

## 잔고 계산 규칙

| 작업 | 현금 변화 | 보유수량·원가 변화 | 수수료 통화 |
| --- | --- | --- | --- |
| 지출 | 출금 계좌에서 금액 + 수수료 차감 | 없음 | 거래 통화 |
| 수입 | 입금 계좌에 금액 - 수수료 가산 | 없음 | 거래 통화 |
| 이체 | 출금 계좌에서 금액 + 수수료 차감, 입금 계좌에 금액 가산 | 없음 | 거래 통화 |
| 환전 | 매도 통화 차감, 매수 통화 가산, 원화 수수료 차감 | 없음 | KRW |
| 주식 매수 | 단가 × 수량 + 수수료 + 세금 차감 | 수량 및 단가 × 수량만큼 원가 증가 | 종목 통화 |
| 주식 매도 | 단가 × 수량 - 수수료 - 세금 가산 | 수량 감소, 평균 원가 × 수량만큼 원가 감소 | 종목 통화 |
| 삭제·수정 | 삭제는 저장된 거래의 변화 취소, 수정은 이전 변화 취소 후 새 변화 적용 | 매도 취소는 기록된 매도금액 - 매도차익으로 원가 복원 | 원래 거래 기준 |

- 일반 거래·환전의 signed amount와 소수는 그대로 계산하고 중간 반올림을 하지 않는다. 환불 등을 나타내는 음수 입력의 기존 의미를 유지한다.
- 기존 매매 코드는 표시용 원가를 소수점 두 자리로 반올림한 뒤 매도 원가 계산에 재사용하지만, 매도차익은 반올림 전 원가로 계산한다. 이 차이는 매매 작업 단위에서 회귀 테스트를 작성하고 바로잡을 대상이다.
- 계좌 등록·수정과 잔고 교체는 같은 EntityManager의 트랜잭션으로 수행한다. 중간 실패 시 이름과 기존 잔고까지 복원한다. 동일 통화의 중복 잔고 및 유한하지 않은 잔고는 서비스에서 거절한다.
- 환전 계좌 수정 누락을 회귀 테스트로 확인했다. 변경 전 `55f6d69` 소스에서는 계좌를 2로 변경해도 조회 결과가 1로 남아 테스트가 실패한다. 변경 후에는 변경 계좌가 저장되고 삭제 시 올바른 계좌 잔고가 복원된다.

### 매매 계산 변경

- 매매의 현금·수량·원가·매도차익 변화를 순수 함수로 분리했다. 매도 원가와 매도차익은 같은 반올림 전 원가를 사용한다. 표시용 두 자리 반올림은 계산에 다시 사용하지 않는다.
- 수정은 이전 효과 취소 후 새 유형으로 계산한다. 매수→매도와 매도→매수 전환의 차익을 각각 검증했다.
- 주식 보유 정보 조회·최초 생성·잔고 변경까지 같은 EntityManager를 전달한다. 최종 보유수량이 음수가 되는 삭제·수정은 트랜잭션을 취소한다. 수정 도중의 일시적인 음수 역산은 허용하고 최종 결과를 검증한다.
- 변경 전 코드에서 부분 매도 원가(20.002 대신 20.003), 유형 전환 차익(6 대신 0), 음수 보유수량을 만드는 삭제가 각각 실패하는 회귀 테스트로 재현됐다.
- 소수 수량 테스트에서 기존 엔티티의 QUANTITY가 Number에서 integer로 추론되어 TypeORM이 소수 부분을 잘라 읽는 문제를 발견했다. 소수 수량 통합 테스트 1개는 명시적으로 보류했고, 6단계를 앞당겨 real 컬럼으로 마이그레이션한 뒤 반드시 재활성화한다. 이 상태는 전체 작업 완료가 아니다.
- 과거 거래 전체의 원가·실현손익을 일괄 재계산하지 않는다. 기존 기록은 유지하고, 새 저장·수정·삭제에서 수정된 계산 규칙을 적용한다.

## DB 마이그레이션 완료

- 6단계를 앞당겨 INTEGER → REAL 업그레이드를 구현하고 보류한 소수 수량 테스트를 재활성화했다. 177개 테스트 모두 통과한다. 절차와 지원 기준은 DB-MIGRATIONS.md에 기록했다.
- 개발 DB 복사본과 arm64 패키지 앱에서 17개 테이블의 모든 행이 보존됨을 확인했다. 신규 DB 초기 데이터, 로그인/preload, 임시 경로의 샘플 생성 CLI도 성공했다. 원본 DB는 변경하지 않았다.
- 패키징 시 기존 외장 볼륨의 한글 경로 정규화로 ZIP 생성이 실패했다. 앱 번들은 생성되고 실행 가능하다. 이 압축 문제와 x64 빌드 후 native 의존성 복원은 7단계의 빌드 작업 단위에서 해결한다.

### 나머지 트랜잭션 경계

- 스냅샷 수정의 기존 행 조회와 하위 데이터 삭제를 트랜잭션 manager로 이동했다. 계좌·잔고·보유종목 조회도 같은 manager를 사용하며, 기다리지 않던 async forEach를 없앴다. 메모 수정·삭제의 조회도 같은 manager를 사용한다.
- 스냅샷 합산은 calculateSnapshotAssets 순수 함수로 분리했다. 기존의 계좌별 현금·매수금·평가금 각각 원화 반올림을 유지한다. 마지막 주식 평가 저장 실패 시 신규 생성과 기존 스냅샷 교체 모두 전체 롤백됨을 테스트했다.

## 모달과 이벤트

- 세 모달의 폼은 forms/ledgerForms.ts와 hooks/use*Form.ts에서 관리한다. yup ObjectSchema를 요청 타입에 맞춰 any와 ts-ignore를 제거했다. 환전·매매 날짜를 문자열로 바꾸던 검증도 Date로 통일했다.
- useModalSession은 조회 세대 번호와 즉시 적용되는 저장 잠금으로 지연 응답 및 중복 제출을 제어한다. 조회 실패 시 기본값을 신규로 저장하지 못하게 막고, 저장 실패 시 입력을 유지한다. 성공 후 목록 새로고침 실패는 완료된 저장의 재실행을 유도하지 않도록 폼을 먼저 닫거나 연속 입력값을 비운다. 자동 재시도하지 않는다.
- useWindowKeydown은 구독 수를 유지하면서 최신 콜백을 읽는다. 수정 ID가 늦게 도착해도 신규용 연속 저장 단축키가 실행되지 않는다. 검색 메뉴 구독은 함수형 상태 갱신과 cleanup으로 중복 등록을 없앴다.
- 동작 수정: 이체의 입금 계좌 0, 양수가 아닌 매매 수량·단가를 폼에서 거절한다. 환전 신규 폼은 KRW와 USD 조합을 기본 선택하며 통화를 변경할 수 있다. 분류 선택창을 새로 열면 이전 선택을 초기화해 다른 거래 유형의 분류가 남지 않게 한다.

## 기준 데이터 소유권

- renderer/state/referenceData.ts가 계좌·분류·종목·보유종목·코드·즐겨찾기 캐시를 소유한다. Mapper는 조회 호환 API와 화면 변환을 맡고, 계좌 선택지 변환은 accountOptions 순수 함수에 인자로 데이터를 전달한다.
- 앱 시작 시 기준 데이터를 로딩하며 실패하면 재시도 버튼을 표시한다. IpcCaller에서 저장 성공 후 영향받는 store만 갱신한다. 거래/환전은 계좌, 매매/보유종목은 계좌와 보유종목, 분류/종목/코드/즐겨찾기는 해당 목록을 갱신한다. 실패한 저장은 갱신하지 않는다.
- 조회 세대 번호로 늦은 응답이 최신 캐시를 덮어쓰지 못하게 한다. 실패한 조회는 이전 캐시를 보존한다. 저장 성공 뒤 갱신 실패는 별도 안내하고 저장 Promise는 성공으로 끝내므로 같은 저장을 재시도하지 않는다.
- 표시 컴포넌트는 useSyncExternalStore 기반 구독으로 다시 그린다. 계좌·종목·보유종목·즐겨찾기 목록과 계좌 합계를 별도 상태에 복제하지 않는다. 각 Electron 창의 캐시는 해당 renderer 수명에 속한다.

## 스냅샷 보고서

- buildSnapshotReport, compareValuations, soldProfit은 전달받은 스냅샷·종목·보유정보만 사용한다. 삭제 표시된 기준 정보도 기존 기록을 해석할 수 있도록 전달한다. 조회·비교 모달은 요청 경합을 차단하고, 계산 실패는 화면 오류로 표시한다.
- 합계·비교·종목·매도 표를 분리했다. 평가금액 셀은 이전 render의 콜백 대신 최신 입력 콜백에 현재 행 데이터를 전달한다. 0인 합계의 비중은 0으로 표시한다. 비교 수익률의 0.1을 0.10%로 표시하던 버그는 10.00%로 수정했다.
- 비교 시 한쪽에만 있는 항목도 유지하고 증감액을 계산한다. 기준 코드가 삭제되었더라도 행을 숨기지 않고 #코드로 표시한다. 환율이 없는 과거 스냅샷은 기존 1 대체 규칙을 유지하되 조회/비교 화면에 누락을 표시한다.
- 새 스냅샷 폼은 요청 스키마를 기반으로 유효한 날짜·양수 환율을 검사하며, 잘못된 환율 오류를 amount 필드에서 읽던 오류도 수정했다.

## 날짜 및 타입 경계

- SQLite DATE 컬럼은 문자열인데 응답 타입은 Date인 불일치를 transformer로 해소했다. DB 저장 형식과 스키마는 바꾸지 않는다. 월별 raw 조회도 명시적 타입과 지역 날짜 변환을 사용하며, UTC 날짜 해석으로 전날/전월이 표시되는 문제를 수정했다.
- 계좌/즐겨찾기 응답의 nullable 필드를 폼 기본값으로 정규화했다. 단언 대신 반환 타입으로 필수 필드를 검증한다. react-table useSortBy의 선언 병합으로 정렬 버튼의 any와 autoResetSortBy의 ts-ignore를 제거했다. 정책과 검증 기준은 DATA-CONVENTIONS.md에 기록했다.

## 화면 조회와 이벤트 수명

- `useLatestRequest`는 조회 세대로 이전 응답·오류와 해제 후 결과를 무시한다. IPC 실행 자체를 취소하지 않으며 저장에는 사용하지 않는다. 달력은 네 종류의 조회를 병렬 실행하고 월 결산은 함께 반영한다.
- FullCalendar의 최초 `datesSet`과 별도 mount effect가 중복 조회하던 코드를 제거했다. 스냅샷 삭제 콜백은 현재 페이지를 새로 조회한다.
- 키보드 이벤트는 최신 콜백을 사용하며 활성 모달에서만 처리한다. 중첩 분류/즐겨찾기 창과 확인 대화상자 뒤의 거래창이 저장되는 것을 막았다.
- 자동완성은 이전 검색 응답을 버리고 선택 키를 소비한다. 숨겨진 선택 항목이 적용되지 않으며 마우스로도 선택할 수 있다.
- 삭제 확인창은 비동기 삭제 완료를 기다려 실패를 한 번 표시한다.
- 검증: 전체 207개 테스트, 타입 검사, 변경 코드 ESLint 오류 없음. `react-hooks/exhaustive-deps` 예외를 모두 제거했다.

## 패키징 및 개발 실행

- macOS에 포함된 7-Zip 16.02가 한글 앱 이름을 NFD로 바꾼 뒤 디렉터리 항목을 찾지 못했다. 외장/내장 APFS의 작은 폴더에서 재현했다. `afterPack`에서 앱 폴더 이름만 NFD로 맞춰 해결했다. 표시 이름·실행 파일·앱 ID는 유지한다.
- 다중 아키텍처 패키징 후 `release/app`에 x64 네이티브 모듈이 남았다. 패키징 스크립트는 성공·실패 모두 현재 아키텍처로 `install-app-deps`를 실행한다. `npm run rebuild`도 같은 설치 경로를 사용한다.
- 실행 스크립트는 Electron 바이너리가 누락되면 재설치 명령을 표시한다. 자동 업데이트의 공개 릴리스가 없는 오류는 로그로 처리하고 Promise 거부를 처리한다.
- 검증: `CSC_IDENTITY_AUTO_DISCOVERY=false npm run package` 전체 성공. arm64/x64 ZIP·DMG 각 1개 및 업데이트 메타데이터 생성, 이후 207개 테스트·타입 검사 통과. 로컬 빌드는 미서명·미공증이며 배포는 하지 않았다.
